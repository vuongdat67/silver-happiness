    Playbook T1-EP01: Phát Hiện Tấn Công Dò Mật Khẩu (Brute Force Windows)¤

    • Kênh nhật ký: Windows Security (EventCode=4625 và 4624).
    • Điều kiện kích hoạt: Trong 5 phút xuất hiện trên 10 bản ghi 4625 thất bại từ cùng một địa chỉ IP.
    • Cú pháp SPL kiểm tra tức thời:
      Bash
      index=windows sourcetype="XmlWinEventLog:Security" EventCode IN (4624, 4625)
| eval is_success = if(EventCode==4624, 1, 0), is_fail = if(EventCode==4625, 1, 0)
| stats sum(is_fail) as total_fails, sum(is_success) as total_success,
        values(TargetUserName) as users, values(SubStatus) as fail_reasons by IpAddress
| where total_fails >= 10
    • Cây quyết định phân loại:
    • False Positive (FP): total_success == 0, IpAddress thuộc máy nội bộ hợp lệ, mã lỗi là 0xC000006A (gõ nhầm pass) do ứng dụng Outlook/Mapped Drive tự động gửi lại mật khẩu cũ. -> Hành động: Đóng ticket, ghi nhận nguyên nhân cache credential, hướng dẫn user cập nhật mật khẩu.
    • True Positive (TP): total_success >= 1 vào chính tài khoản bị brute force (kẻ tấn công đã dò trúng mật khẩu), hoặc cùng 1 IP thử danh sách dài trên 10 user khác nhau (Password Spraying). -> Hành động: Khóa tài khoản ngay, chuyển giao khẩn cấp lên Tier 2.

    Playbook T1-EP18: Truy Cập Bộ Nhớ Tiến Trình LSASS (Nghi Ngờ Mimikatz)¤

    • Kênh nhật ký: Sysmon EventCode=10 (TargetImage="*\\lsass.exe").
    • Cú pháp SPL kiểm tra:
      Bash
      index=windows sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=10 TargetImage="*\\lsass.exe"
| search GrantedAccess IN ("0x1010", "0x1410", "0x1438", "0x1FFFFF")
| search NOT SourceImage IN ("*\\MsMpEng.exe", "*\\csfalconservice.exe", "*\\WazuhAgent.exe")
| table _time host SourceImage TargetImage GrantedAccess CallTrace
    • Cây quyết định:
    • FP: SourceImage là tiến trình bảo mật chính hãng có chữ ký số hợp lệ (MsMpEng.exe). -> Đóng ticket, tune whitelist chữ ký.
    • TP: SourceImage là powershell.exe, rundll32.exe, procdump.exe, taskmgr.exe hoặc tiến trình không rõ nguồn gốc. -> Escalate P1 ngay lập tức lên Tier 2 để cô lập máy.

    Playbook T1-WB02: Hành Vi Khai Thác Web Shell Qua Yêu Cầu HTTP POST¤

    • Kênh nhật ký: Web Server Access Log (IIS/Apache/Nginx).
    • Cú pháp SPL kiểm tra:
      Bash
      index=web_proxy cs_method=POST cs_uri_stem IN ("*.aspx", "*.php", "*.jsp")
| stats count as total_requests,
        count(eval(sc_status==200)) as success_requests,
        avg(sc_bytes) as avg_response_size by c_ip cs_uri_stem
| eval success_ratio = round((success_requests / total_requests) * 100, 2)
| where total_requests >= 5 AND success_ratio >= 80 AND avg_response_size > 500
    • Cây quyết định:
    • FP: Endpoint là API upload hoặc form quản trị CMS hợp lệ của công ty.
    • TP: Tệp tin nằm trong thư mục tĩnh (/uploads/, /assets/, C:\inetpub\wwwroot\images\), nhận các truy vấn POST kèm tham số lệnh và trả về HTTP 200. -> Escalate Tier 2 can thiệp xóa file.

    2.2. Kịch Bản Cô Lập Mạng Khẩn Cấp (Emergency Network Containment)¤

    Mục tiêu của cô lập là cắt đứt hoàn toàn liên lạc của máy bị nhiễm với mạng nội bộ và máy chủ điều khiển C2 ngoài Internet, nhưng bắt buộc phải giữ lại luồng kết nối tới máy chủ Splunk SIEM / EDR Console để tiếp tục giám sát.

    Kịch Bản 1: Cô lập máy trạm Windows bằng dòng lệnh PowerShell / Netsh¤

    Nếu hệ thống không có EDR Agent hỗ trợ nút bấm "Isolate", chuyên viên L2 thực thi kịch bản sau qua phiên quản trị từ xa hoặc can thiệp trực tiếp:

    PowerShell
    # Bật toàn bộ tường lửa Windows
netsh advfirewall set allprofiles state on

# Đặt chính sách mặc định: Chặn toàn bộ Inbound và Outbound
netsh advfirewall set allprofiles firewallpolicy blockinbound,blockoutbound

# Xóa bỏ các rule tạm gây xung đột
netsh advfirewall firewall delete rule name="SOC_Allow_SIEM"
netsh advfirewall firewall delete rule name="SOC_Allow_DNS"

# Mở ngoại lệ duy nhất: Cho phép đẩy log về Splunk Indexer (IP 192.168.100.10, Port 9997)
netsh advfirewall firewall add rule name="SOC_Allow_SIEM" dir=out action=allow protocol=TCP remoteip=192.168.100.10 remoteport=9997

# Mở ngoại lệ cổng phân giải DNS nội bộ để EDR hoạt động (Domain Controller 192.168.100.50)
netsh advfirewall firewall add rule name="SOC_Allow_DNS" dir=out action=allow protocol=UDP remoteip=192.168.100.50 remoteport=53

    Kịch Bản 2: Cô lập máy chủ Linux bằng iptables¤

    Bash
    # Lưu cấu hình iptables hiện tại vào file backup
iptables-save > /root/iptables_backup.rules

# Chặn đứng toàn bộ lưu lượng vào/ra mặc định

iptables -P OUTPUT DROP

iptables -A INPUT -p tcp -s 192.168.100.10 --sport 9997 -m state --state ESTABLISHED -j ACCEPT

# Cho phép loopback nội bộ hệ điều hành
iptables -A INPUT -i lo -j ACCEPT
iptables -A OUTPUT -o lo -j ACCEPT

    Chuyên viên SOC Tier 3 chịu trách nhiệm xử lý các bài toán nâng cao: phân tích mẫu độc do Tier 2 bàn giao, chủ động đi săn các mối đe dọa ẩn mình chưa nổ cảnh báo (Proactive Threat Hunting) và hoàn thiện vòng lặp kỹ nghệ phát hiện (Detection Engineering Loop).

    3.1. Kịch Bản Săn Lùng Mối Đe Dọa Chủ Động (Hypothesis-Driven Threat Hunting)¤

    Giả Thuyết 1: Attacker tiêm mã độc vào tiến trình hợp lệ nhưng không lưu tệp (Process Injection)¤

    • Kỹ thuật MITRE: T1055 (Process Injection), T1055.012 (Process Hollowing).
    • Truy vấn săn lùng Splunk (Đối soát CreateRemoteThread lạ):
      Bash
      index=windows sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=8
| search TargetImage IN ("*\\explorer.exe", "*\\svchost.exe", "*\\lsass.exe", "*\\spoolsv.exe")
| search NOT SourceImage IN ("*\\csfalconservice.exe", "*\\MsMpEng.exe", "*\\vmtoolsd.exe")
| stats count values(SourceImage) as Injected_By, values(TargetImage) as Target, values(StartFunction) as Function by host StartAddress
| where count < 5

    Giả Thuyết 2: Attacker lạm dụng tiến trình Living-off-the-Land (LOLBins) để kết nối ra ngoài¤

    • Truy vấn săn lùng: Tìm các công cụ quản trị hệ thống (certutil, bitsadmin, powershell, mshta) phát sinh kết nối mạng ra ngoài Internet:
      Bash
      index=windows sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=3 Initiated=true
| search Image IN ("*\\certutil.exe", "*\\bitsadmin.exe", "*\\mshta.exe", "*\\regsvr32.exe", "*\\cscript.exe", "*\\wscript.exe")
| where NOT cidrmatch("10.0.0.0/8", DestinationIp) AND NOT cidrmatch("192.168.0.0/16", DestinationIp) AND NOT cidrmatch("172.16.0.0/12", DestinationIp)
| stats count earliest(_time) as first_seen latest(_time) as last_seen by host User Image DestinationIp DestinationPort

    3.2. Quy Trình Phân Tích Mẫu Mã Độc (Malware Analysis Checklist)¤

    Khi nhận tệp nhị phân từ Tier 2, Tier 3 thực hiện phân tích trong môi trường mạng cô lập (Sandbox / Remnux):

    1. Phân Tích Tĩnh (Static Analysis):
    2. Tính hàm băm tệp: sha256sum sample.exe -> Kiểm tra trên VirusTotal / AlienVault OTX.
    3. Trích xuất chuỗi ký tự văn bản:
      Bash
      strings -a -n 8 sample.exe | grep -iE "http|https|\.dll|\.pdb|powershell|cmd|reg add|token"
    4. Nhận diện Packer / Cryptor: Kiểm tra độ entropy bằng Detect It Easy (DIE). Nếu entropy > 7.2, tệp tin đã bị mã hóa hoặc nén bằng UPX, Themida.

    5. Soi bảng Import Table (PEStudio / CFF Explorer):

      • Các hàm nguy hiểm: VirtualAllocEx, WriteProcessMemory, CreateRemoteThread (dấu hiệu tiêm mã Process Injection).
      • AdjustTokenPrivileges, OpenProcessToken (dấu hiệu leo thang đặc quyền).

    6. Viết Luật Nhận Diện Mẫu Mã Độc (YARA Rule Authoring): Tạo quy tắc YARA để nạp vào EDR/Wazuh quét toàn bộ ổ cứng máy trạm trong doanh nghiệp:

        $hex_shellcode = { 48 83 EC 28 48 89 4C 24 20 48 8D 0D ?? ?? ?? ?? E8 ?? ?? ?? ?? }
    condition:
        uint16(0) == 0x5A4D and (2 of ($str*) or $hex_shellcode)
}

    3.3. Khép Kín Vòng Lặp Kỹ Nghệ Phát Hiện (Closed-Loop Detection Engineering)¤

    Để ngăn chặn cuộc tấn công tương tự xảy ra trong tương lai, Tier 3 bắt buộc phải biến bài học thành luật phòng thủ tự động:

    1. Thực thi kiểm thử giả lập tấn công (Atomic Red Team Validation): Sử dụng framework Atomic Red Team để mô phỏng lại kỹ thuật tấn công vừa xảy ra trên máy lab nhằm kiểm tra cảm biến có bắt được hay không:
      PowerShell
      # Giả lập kỹ thuật T1003.001 (LSASS Dump bằng comsvcs.dll)
Invoke-AtomicTest T1003.001 -TestNumbers 1
    2. Triển khai luật phát hiện mới lên Splunk SIEM: Chuyển đổi bài học thành Correlation Search hoặc Sigma Rule mới, gán nhãn MITRE ATT&CK và kích hoạt cảnh báo tự động về cho Tier 1.
    3. Báo cáo phân tích nguyên nhân gốc rễ (Root Cause Analysis - RCA): Soạn thảo báo cáo kỹ thuật hoàn chỉnh: Kẻ tấn công vào bằng con đường nào (Initial Access Vector)? Lỗ hổng nào chưa được vá? Cơ chế nào của hệ điều hành bị lợi dụng? Đề xuất kiến trúc phòng thủ cứng hóa (Hardening Recommendations) cho ban lãnh đạo.

    2. Kênh Nhật Ký Windows: Phân Tích Trường Chi Tiết Theo Từng Sự Kiện¤

    Sự Kiện Xác Thực: 4624 (Thành Công) và 4625 (Thất Bại)¤

    • Danh mục trường dữ liệu cốt lõi:
    • SubjectUserSid / SubjectUserName / SubjectLogonId: Danh tính và mã phiên của tài khoản yêu cầu thực hiện hành vi đăng nhập.
    • TargetUserSid / TargetUserName / TargetDomainName: Danh tính tài khoản thực tế đang cố gắng đăng nhập.
    • TargetLogonId: Khóa duy nhất (Hex, ví dụ 0x3E7 cho SYSTEM, 0x12A4B cho người dùng) đại diện cho phiên đăng nhập vừa tạo. Đây là trường liên kết số 1 để truy vết xem tiến trình độc hại chạy trong phiên đăng nhập của ai.
    • LogonType: Mã số đại diện cho phương thức người dùng xác thực vào hệ điều hành.
    • LogonProcessName: Phân hệ xử lý xác thực (ví dụ User32, Kerberos, NtLmSsp, Advapi).
    • AuthenticationPackageName: Gói bảo mật xác thực (Negotiate, Kerberos, NTLM).
    • WorkstationName: Tên NetBIOS của máy trạm gửi yêu cầu xác thực.
    • IpAddress: Địa chỉ IPv4/IPv6 của nguồn kết nối (nếu là - hoặc 127.0.0.1 nghĩa là đăng nhập cục bộ).
    • IpPort: Cổng dịch vụ nguồn phía máy khách.
    • Status / SubStatus: Mã lỗi nguyên nhân từ chối phiên đăng nhập (chỉ có trong sự kiện 4625).

    Bảng Tra Cứu Chuyên Sâu Mã LogonType¤

    LogonType Tên Kỹ Thuật Ý Nghĩa Thực Tế Kịch Bản SOC Cần Điều Tra
    Type 2 Interactive Người dùng ngồi trực tiếp trước bàn phím máy tính hoặc gõ qua bảng điều khiển máy ảo (Console). Xuất hiện ngoài giờ làm việc trên máy trạm của nhân sự đã tan sở.
    Type 3 Network Kết nối từ xa qua chia sẻ tài nguyên mạng SMB (\\server\c$, IPC$, RPC, IIS). Di chuyển ngang (Lateral Movement) bằng PsExec, WMI, SMBExec; tấn công Password Spraying qua mạng nội bộ.
    Type 4 Batch Hệ thống Windows Task Scheduler kích hoạt tác vụ chạy ngầm định kỳ. Kẻ tấn công duy trì mã độc qua cơ chế Scheduled Task tự kích hoạt.
    Type 5 Service Dịch vụ hệ thống khởi động dưới danh tính tài khoản dịch vụ được chỉ định. Dịch vụ mã độc được cài đặt tự kích hoạt lúc khởi động máy.
    Type 7 Unlock Người dùng nhập mật khẩu để mở khóa màn hình Workstation. Kiểm tra thời gian làm việc thực tế của nhân sự.
    Type 8 NetworkCleartext Xác thực gửi mật khẩu dạng văn bản rõ không mã hóa qua mạng (ví dụ Basic Authentication trên IIS). Rủi ro bị bắt gói tin nghe lén nội bộ (Sniffing).
    Type 9 NewCredentials Lệnh runas /netonly được thực thi để mượn danh tính tài khoản khác khi ra ngoài mạng trong khi vẫn giữ nguyên danh tính cục bộ. Kỹ thuật kinh điển của Mimikatz Pass-the-Hash hoặc dùng công cụ Cobalt Strike mượn vé Kerberos.
    Type 10 RemoteInteractive Đăng nhập giao diện đồ họa từ xa qua giao thức Remote Desktop Protocol (RDP). Đăng nhập RDP trái phép từ ngoài Internet hoặc kỹ thuật RDP Pivoting di chuyển giữa các máy trạm.
    Type 11 CachedInteractive Đăng nhập vào máy trạm bằng bản băm mật khẩu được lưu tạm trong bộ nhớ cục bộ khi máy bị mất kết nối tới Domain Controller. Nhân viên làm việc từ xa hoặc máy trạm bị cô lập mạng nhưng kẻ tấn công vẫn đăng nhập được.

    Bảng Tra Cứu Mã Lỗi Xác Thực SubStatus (Điểm Nóng Trong Event 4625)¤

    Mã SubStatus (Hex) Nguyên Nhân Kỹ Thuật Dấu Hiệu Tác Chiến Của Attacker
    0xC000006D Bad username or authentication information Tên tài khoản hoặc mật khẩu bị sai chung chung.
    0xC000006A User name is correct but password is invalid Tên tài khoản tồn tại chính xác nhưng nhập sai mật khẩu (chứng tỏ kẻ tấn công đã biết tên user).
    0xC0000064 User name does not exist Tên tài khoản không hề tồn tại trong Active Directory (chỉ điểm rõ tấn công rà quét vét từ điển User Enumeration).
    0xC0000234 The user account has been automatically locked Tài khoản bị khóa do vượt quá số lần nhập sai liên tiếp cho phép (Account Lockout Policy).
    0xC0000072 Account is currently disabled Tài khoản đang bị vô hiệu hóa bởi chính sách quản trị (kẻ tấn công cố tình thử tài khoản nghỉ việc).
    0xC0000193 Account expiration date has passed Tài khoản nhân sự thời vụ đã hết hạn sử dụng.
    0xC0000224 User is required to change password at next logon Tài khoản bắt buộc phải đổi mật khẩu ở lần đăng nhập đầu tiên.

    Sự Kiện Tiến Trình: 4688 (Khởi Tạo) và 4689 (Kết Thúc)¤

    • Danh mục trường dữ liệu cốt lõi:
    • SubjectLogonId: Khóa liên kết phiên người dùng thực thi lệnh.
    • NewProcessId: Mã định danh tiến trình PID (dạng Hex, ví dụ 0x1A4).
    • NewProcessName: Đường dẫn đầy đủ của tệp tin thực thi (ví dụ C:\Windows\System32\cmd.exe).
    • CommandLine: Chuỗi câu lệnh đầy đủ kèm tham số (cần bật GPO Include Command Line).
    • ParentProcessName: Tệp tin thực thi của tiến trình cha đã sinh ra tiến trình này.
    • TokenElevationType: Mức nâng quyền UAC của tiến trình:
      • TokenElevationTypeDefault (1): Người dùng bình thường hoặc UAC bị tắt.
      • TokenElevationTypeFull (2): Tiến trình chạy với quyền quản trị viên nâng cao (Elevated - Run as Administrator).
      • TokenElevationTypeLimited (3): Người dùng thuộc nhóm Administrators nhưng tiến trình chạy ở mức quyền hạn chế chưa bấm xác nhận UAC.

    Sự Kiện Dịch Vụ và Lập Lịch: 7045 (System) và 4698 (Security)¤

    • EventID 7045 (System - Dịch vụ mới được cài đặt):
    • ServiceName: Tên định danh của dịch vụ trong hệ thống (ví dụ PSEXESVC, wuauserv).
    • ImagePath: Đường dẫn tệp tin nhị phân và tham số nạp dịch vụ.
    • ServiceType: Loại hình dịch vụ (user mode service, kernel mode driver).
    • StartType: Chế độ khởi động (auto start, demand start, disabled).

    • AccountName: Tài khoản mà dịch vụ sẽ chạy dưới quyền (LocalSystem, LocalService, Domain\Account).

    • EventID 4698 (Security - Lập lịch Scheduled Task mới):

    • TaskName: Tên của tác vụ lập lịch trong cây Task Scheduler.
    • TaskContent: Cấu trúc XML chứa toàn bộ định nghĩa tác vụ: trigger kích hoạt, đường dẫn tệp thực thi <Command>, tham số <Arguments>, tài khoản chạy <UserId>.

    3. Kênh Nhật Ký Linux: Cấu Trúc Bản Ghi và Từ Điển Trường Auditd¤

    Khác với định dạng XML của Windows, Linux Auditd lưu vết ở dạng chuỗi văn bản phân tách bằng dấu cách kèm cặp khóa-giá trị (key=value):

    Text Only
    type=SYSCALL msg=audit(1693248102.123:456): arch=c000003e syscall=59 success=yes exit=0 a0=55e1a a1=55e1b a2=55e1c a3=0 items=2 ppid=1420 pid=2105 auid=1000 uid=0 gid=0 euid=0 suid=0 fsuid=0 egid=0 sgid=0 fsgid=0 tty=pts0 ses=3 comm="bash" exe="/bin/bash" key="priv-escalation"

    Từ Điển Các Trường Dữ Liệu Trong Bản Ghi type=SYSCALL¤

    Tên Trường Định Nghĩa Kỹ Thuật Ứng Dụng Tác Chiến Trong Điều Tra SOC
    msg=audit(time:id) Epoch timestamp và ID sự kiện duy nhất. Khóa liên kết toàn bộ bản ghi con (EXECVE, PATH, CWD) cùng một lệnh.
    arch Mã kiến trúc CPU (ví dụ c000003e đại diện cho x86_64). Phát hiện mã độc 32-bit chạy trên hệ điều hành 64-bit nhằm qua mặt sensor.
    syscall Số hiệu System Call trong kernel (ví dụ 59 là execve, 42 là connect). Nhận diện hành vi nền tảng của tiến trình.
    success Kết quả thực thi của syscall (yes hoặc no). Đánh giá đòn tấn công có khai thác thành công hay bị quyền hạn từ chối.
    exit Mã thoát trả về từ System Call (0 là thành công, âm là lỗi). Đối soát lỗi EACCES (-13) hoặc ENOENT (-2).
    a0, a1, a2, a3 Bốn tham số đầu tiên truyền vào System Call ở tầng assembly. Bóc tách địa chỉ socket mạng hoặc con trỏ bộ nhớ.
    pid Process ID của tiến trình thực hiện lệnh. Truy vết cây tiến trình trên Linux.
    ppid Parent Process ID của tiến trình cha. Phát hiện quan hệ bất thường: web server (apache) sinh ra shell.
    auid Audit User ID (Định danh đăng nhập gốc). Trường sống còn: Dù hacker có gõ sudo su - lên root, auid vẫn giữ nguyên ID người dùng ban đầu đăng nhập qua SSH.
    uid / euid User ID thực tế và Effective User ID tại thời điểm chạy. Phát hiện leo thang đặc quyền khi uid=1000 nhưng euid=0 (root).
    comm Tên ngắn của lệnh thực thi (tối đa 16 ký tự). Nhận diện nhanh lệnh: cat, curl, nmap.
    exe Đường dẫn tệp tin thực thi tuyệt đối trên đĩa. Phát hiện binary chạy từ thư mục bất thường: /tmp/nc, /dev/shm/.x.
    key / k Nhãn phân loại do chuyên viên SOC cấu hình trong audit.rules. Gom nhóm sự kiện phục vụ tương quan trên SIEM (key="identity_tampering").

    Các Loại Bản Ghi Bổ Trợ Đi Kèm Trong Cùng Một Giao Dịch Auditd¤

    • type=EXECVE: Cung cấp đầy đủ toàn bộ đối số dòng lệnh:
    • argc: Số lượng tham số truyền vào.
    • a0: Lệnh gốc (ví dụ "python").
    • a1, a2, a3: Tham số tương ứng (ví dụ a1="-c", a2="import socket,pty;...").
    • type=PATH: Ghi nhận tệp tin bị hệ thống tác động:
    • name: Đường dẫn tệp tin bị truy cập/chỉnh sửa.
    • nametype: Loại hành vi (CREATE, DELETE, NORMAL).
    • mode: Quyền hạn tệp tin (ví dụ octal 0104755 chỉ điểm tệp tin có cờ SUID).
    • type=SOCKADDR: Ghi nhận thông tin địa chỉ kết nối mạng socket:
    • saddr: Chuỗi Hex chứa cấu trúc sockaddr_in (Family, Port Hex, IP Hex). Cần viết parser trên Splunk để chuyển về dạng IP:Port chuẩn.

    4. Kênh Nhật Ký Tường Lửa Doanh Nghiệp (Palo Alto và Fortinet)¤

    Tường lửa thế hệ mới (NGFW) cung cấp bối cảnh lưu lượng mạng ở tầng biên, giúp chuyên viên SOC xác định lưu lượng độc hại có thoát được ra ngoài (Egress) hoặc xâm nhập thành công vào vùng máy chủ nội bộ hay không.

    Bảng Trường Dữ Liệu Tường Lửa Palo Alto (sourcetype=pan:traffic và pan:threat)¤

    Tên Trường Palo Alto Kiểu Dữ Liệu Mô Tả Ý Nghĩa Kịch Bản Kiểm Tra Cho SOC
    src / src_ip IP Address Địa chỉ IP máy nguồn phát sinh kết nối. Nhận diện máy trạm nội bộ bị nhiễm hoặc IP tấn công bên ngoài.
    sport / src_port Integer Cổng dịch vụ phía nguồn. Nhận diện cổng nguồn cao (>1024) của client.
    dst / dest_ip IP Address Địa chỉ IP đích nhận kết nối. Đối soát với cơ sở dữ liệu Threat Intel (C2 Server, Malicious IP).
    dport / dest_port Integer Cổng dịch vụ đích. Phát hiện kết nối ra cổng bất thường: 4444, 1337, 6667.
    proto String Giao thức tầng mạng (tcp, udp, icmp). Phân loại lưu lượng truyền thông.
    app String Ứng dụng tầng L7 do engine App-ID nhận diện. Điểm nóng: Ứng dụng là ms-ds-smb đi ra Internet, hoặc ssl chạy trên cổng non-standard 8080.
    action String Quyết định xử lý của Firewall: allow, deny, drop, reset-client, reset-server, reset-both. Xác định đòn tấn công đã bị chặn (drop) hay đã đi lọt qua (allow).
    bytes / bytes_sent / bytes_received Integer Tổng số byte dữ liệu truyền tải giữa hai đầu kết nối. Săn lùng rò rỉ dữ liệu (Exfiltration): bytes_sent vượt ngưỡng hàng chục MB ra ngoài.
    threat_name String Tên chữ ký mối đe dọa (trong nhật ký Threat). Tên mã độc hoặc lỗ hổng: Web Shell Detected, SQL Injection.
    severity String Mức độ nghiêm trọng: informational, low, medium, high, critical. Lọc cảnh báo ưu tiên xử lý trong ca trực.
    category String Phân loại tên miền/URL (PAN-DB URL Filtering). Các danh mục rủi ro cao: malware, command-and-control, dynamic-dns, unknown.

    Bảng Trường Dữ Liệu Tường Lửa Fortinet FortiGate (sourcetype=fgt_traffic và fgt_utm)¤

    • srcip, dstip, srcport, dstport: Thông tin bốn góc định danh luồng mạng.
    • service: Tên dịch vụ mạng được định nghĩa trong chính sách (HTTP, HTTPS, DNS, SSH).
    • policyid: ID của chính sách tường lửa cho phép lưu lượng đi qua.
    • action: Trạng thái xử lý (accept, deny, close, timeout).
    • sentbyte, rcvdbyte: Dung lượng gửi và nhận tính theo byte.
    • crscore / crlevel: Điểm rủi ro tổng hợp (Corporate Risk Score) được FortiGate đánh giá tự động dựa trên hành vi kết nối.

    5. Kênh Nhật Ký Cảm Biến EDR (CrowdStrike, Defender for Endpoint và Wazuh)¤

    Cảm biến EDR cung cấp khả năng phát hiện hành vi ở mức tiến trình và bộ nhớ chi tiết hơn nhật ký hệ điều hành truyền thống:

    Danh Mục Trường Cốt Lõi Của CrowdStrike Falcon¤

    • aid (Agent ID): Chuỗi định danh duy nhất của tác nhân EDR cài trên máy trạm (khóa liên kết toàn bộ sự kiện của máy đó).
    • ComputerName: Tên máy tính trong hệ thống mạng.
    • DetectName / DetectDescription: Tên định danh phát hiện mã độc và mô tả kỹ thuật của hãng.
    • SeverityName: Mức độ nghiêm trọng (Critical, High, Medium, Low).
    • Tactic / Technique: Chiến thuật và mã kỹ thuật ánh xạ trực tiếp theo ma trận MITRE ATT&CK (ví dụ Persistence / T1547.001).
    • FileName / FilePath: Tên và đường dẫn tuyệt đối của tệp tin bị phát hiện.
    • SHA256HashData: Mã băm SHA-256 duy nhất của tệp mã độc phục vụ đối soát VirusTotal và bẻ khóa IOC.
    • CommandLine: Dòng lệnh khởi chạy của tiến trình độc hại.
    • ParentCommandLine: Dòng lệnh của tiến trình cha.
    • PatternDisposition: Cờ nhị phân đại diện cho hành động phòng vệ tự động của EDR:
    • Đã diệt/ngăn chặn: Process Terminated, File Quarantined, Registry Modified.
    • Chưa chặn (chỉ ghi nhận): Detection Only.

    Danh Mục Trường Cốt Lõi Của Wazuh Open Source EDR¤

    • agent.id / agent.name: Định danh tác nhân Wazuh.
    • rule.id: Mã hiệu luật phát hiện của Wazuh (ví dụ 5710 là SSH Brute Force).
    • rule.level: Cấp độ cảnh báo từ 1 đến 16 (cấp độ 12 trở lên cần can thiệp khẩn cấp).
    • rule.description: Mô tả chi tiết hành vi bị vi phạm.
    • rule.mitre.id: Mã kỹ thuật MITRE ATT&CK đi kèm.
    • data.win.system.eventID: Mã EventCode gốc nếu nguồn dữ liệu là Windows Event.

    EventID 1: Process Creation (Khởi Tạo Tiến Trình)¤

    • Ý nghĩa: Ghi nhận mọi tiến trình mới được sinh ra trong hệ điều hành kèm thông tin cha, dòng lệnh, hàm băm và mức toàn vẹn.
    • Trường dữ liệu cốt lõi: UtcTime, ProcessGuid, ProcessId, Image, CommandLine, CurrentDirectory, User, LogonId, IntegrityLevel, Hashes, ParentProcessGuid, ParentProcessId, ParentImage, ParentCommandLine.
    • Dấu hiệu đáng ngờ:
    • Quan hệ cha con bất thường: winword.exe, excel.exe, outlook.exe, w3wp.exe sinh trực tiếp cmd.exe, powershell.exe, mshta.exe, rundll32.exe.
    • Lạm dụng công cụ nội tại (LOLBins): certutil.exe -urlcache -split -f http..., bitsadmin.exe /transfer..., mshta.exe vbscript:..., regsvr32.exe /s /u /i:http....
    • Dòng lệnh obfuscation: Tham số mã hóa Base64 (-enc, -EncodedCommand), gọi tắt (-w hidden, IEX, Invoke-Expression).
    • Truy vấn Splunk kiểm tra:
      Bash
      index=windows sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
| eval is_suspicious=case(
    match(ParentImage, "(?i)(winword|excel|powerpnt|outlook|w3wp)\.exe") AND match(Image, "(?i)(cmd|powershell|mshta|rundll32|wscript)\.exe"), "Malicious_Parent_Child",
    match(CommandLine, "(?i)(-enc|-encodedcommand|-w\s+hidden|certutil\s+-urlcache|bitsadmin\s+/transfer)"), "Suspicious_CommandLine",
    1=1, "Normal"
  )
| where is_suspicious!="Normal"
| table _time host User ParentImage Image CommandLine is_suspicious

    EventID 5: Process Terminate (Kết Thúc Tiến Trình)¤

    • Ý nghĩa: Tiến trình kết thúc hoạt động hoặc bị cưỡng chế đóng bởi tiến trình khác.
    • Trường dữ liệu cốt lõi: UtcTime, ProcessGuid, ProcessId, Image.
    • Ứng dụng điều tra: Không cấu hình cảnh báo đơn lẻ. Sử dụng để đo lường thời gian tồn tại (Dwell Time) của mã độc hoặc đối soát thời điểm phần mềm diệt virus/tiến trình bảo mật bị kẻ tấn công tắt đột ngột trước khi thực hiện bước tiếp theo.

    Phân Nhóm 2: Mạng và Phân Giải Tên Miền (Network và DNS)¤

    EventID 3: Network Connection (Kết Nối Mạng Đi/Đến)¤

    • Ý nghĩa: Ghi nhận các kết nối giao thức TCP/UDP được khởi tạo bởi tiến trình cục bộ ra máy chủ bên ngoài hoặc nhận từ mạng ngoài.
    • Trường dữ liệu cốt lõi: Image, User, Protocol, Initiated, SourceIp, SourcePort, DestinationIp, DestinationPort, DestinationHostname.
    • Dấu hiệu đáng ngờ:
    • Tiến trình hệ thống không bao giờ cần ra Internet lại khởi tạo kết nối: spoolsv.exe, lsass.exe, svchost.exe (không qua dịch vụ hệ thống chuẩn), wordpad.exe.
    • Cổng đích bất thường: Kết nối ra cổng lạ 4444, 8080, 8443, 1337, 6667 hoặc kết nối ra ngoài qua cổng DNS 53/TCP.
    • Truy vấn Splunk kiểm tra:
      Bash
      index=windows sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=3 Initiated=true
| search Image IN ("*\\powershell.exe", "*\\cmd.exe", "*\\rundll32.exe", "*\\lsass.exe", "*\\spoolsv.exe")
| stats count earliest(_time) as first_seen latest(_time) as last_seen by host User Image DestinationIp DestinationPort
| where NOT cidrmatch("10.0.0.0/8", DestinationIp) AND NOT cidrmatch("192.168.0.0/16", DestinationIp) AND NOT cidrmatch("172.16.0.0/12", DestinationIp)
| sort - count

    EventID 22: DNS Query (Phân Giải Tên Miền)¤

    • Ý nghĩa: Tiến trình thực hiện truy vấn tên miền DNS bất kể thành công hay thất bại.
    • Trường dữ liệu cốt lõi: ProcessGuid, Image, QueryName, QueryStatus, QueryResults.
    • Dấu hiệu đáng ngờ:
    • Thuật toán sinh tên miền tự động (DGA): Tên miền độ dài lớn, chuỗi ký tự ngẫu nhiên entropy cao (x8a9b2c3d4f.top).
    • Kênh ngầm DNS (DNS Tunneling): Truy vấn liên tục các subdomain dạng dữ liệu mã hóa Base64/Hex gửi kèm bản ghi TXT/CNAME.
    • Tiến trình shell thực hiện phân giải: powershell.exe, cmd.exe, certutil.exe gọi trực tiếp DNS Query.

    Phân Nhóm 3: Bộ Nhớ, Tiêm Mã và Trích Xuất Thông Tin Xác Thực (Memory, Injection và Credentials)¤

    EventID 7: Image Loaded (Nạp Thư Viện Động DLL)¤

    • Ý nghĩa: Ghi nhận module/DLL được nạp vào không gian bộ nhớ của tiến trình, đi kèm trạng thái chữ ký số.
    • Trường dữ liệu cốt lõi: Image, ImageLoaded, Hashes, Signed, Signature, SignatureStatus.
    • Dấu hiệu đáng ngờ:
    • Kỹ thuật DLL Sideloading: Tiến trình hợp lệ nạp DLL giả mạo đặt cùng thư mục người dùng (C:\Users\...\AppData).
    • DLL không có chữ ký số hợp lệ (Signed=false hoặc SignatureStatus!=Valid) được nạp vào các tiến trình nhạy cảm như lsass.exe, winlogon.exe.

    EventID 8: CreateRemoteThread (Tiêm Tiểu Trình Từ Xa)¤

    • Ý nghĩa: Một tiến trình (SourceImage) tạo một tiểu trình mới bên trong không gian bộ nhớ của tiến trình mục tiêu (TargetImage).
    • Trường dữ liệu cốt lõi: SourceProcessGuid, SourceImage, TargetProcessGuid, TargetImage, StartAddress, StartModule, StartFunction, NewThreadId.
    • Dấu hiệu đáng ngờ:
    • Kỹ thuật Process Injection (MITRE ATT&CK T1055): Tiến trình lạ tiêm vào các tiến trình hệ thống cốt lõi (explorer.exe, svchost.exe, lsass.exe, spoolsv.exe).
    • StartModule hoặc StartFunction để trống hoặc trỏ vào vùng nhớ không thuộc module hệ thống nào (Unbacked Memory Region).

    EventID 10: ProcessAccess (Mở Quyền Truy Cập Bộ Nhớ Tiến Trình)¤

    • Ý nghĩa: Tiến trình mở handle truy cập tiến trình khác với các cờ đặc quyền cụ thể (GrantedAccess).
    • Trường dữ liệu cốt lõi: SourceImage, TargetImage, GrantedAccess, CallTrace.
    • Dấu hiệu đáng ngờ:
    • Trích xuất thông tin xác thực bộ nhớ (LSASS Credential Dumping): TargetImage kết thúc bằng lsass.exe với mã quyền hạn nguy hiểm:
      • 0x1010: PROCESS_QUERY_LIMITED_INFORMATION kết hợp PROCESS_VM_READ.
      • 0x1410: Quyền đọc dữ liệu bộ nhớ ảo và thông tin luồng.
      • 0x1438: Quyền đọc bộ nhớ kèm nhân bản handle (PROCESS_DUP_HANDLE).
      • 0x1FFFFF: Toàn quyền kiểm soát tiến trình (PROCESS_ALL_ACCESS).
    • Truy vấn Splunk kiểm tra:
      Bash
      index=windows sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=10 TargetImage="*\\lsass.exe"
| search GrantedAccess IN ("0x1010", "0x1410", "0x1438", "0x1FFFFF")
| search NOT SourceImage IN ("*\\MsMpEng.exe", "*\\csfalconservice.exe", "*\\EDR_Agent.exe")
| stats count min(_time) as first_seen max(_time) as last_seen by host SourceImage TargetImage GrantedAccess CallTrace
| sort - count

    EventID 25: Process Tampering (Làm Xáo Trộn Tiến Trình)¤

    • Ý nghĩa: Phát hiện kỹ thuật can thiệp cấu trúc tiến trình như Process Hollowing, Process Herpaderping, Process Doppelganging.
    • Trường dữ liệu cốt lõi: UtcTime, ProcessGuid, Image, Type.
    • Hành động xử lý: Tỷ lệ cảnh báo giả rất thấp. Khi xuất hiện Event 25, SOC cần coi đây là sự cố nghiêm trọng cấp độ cao, tiến hành cô lập máy trạm và trích xuất bộ nhớ tiến trình ngay lập tức.

    Phân Nhóm 4: Hệ Thống Tập Tin và Xóa Dấu Vết (File System và Anti-Forensics)¤

    EventID 2: File Creation Time Changed (Timestomping)¤

    • Ý nghĩa: Thời gian khởi tạo của tập tin (CreationUtcTime) bị chỉnh sửa can thiệp thủ công.
    • Trường dữ liệu cốt lõi: Image, TargetFilename, CreationUtcTime, PreviousCreationUtcTime.
    • Dấu hiệu đáng ngờ: Kẻ tấn công sao chép mốc thời gian từ các tệp tin hệ thống như kernel32.dll gán cho mã độc vừa tải về nhằm đánh lừa điều tra viên sử dụng phương pháp đối soát thời gian (T1070.006).

    EventID 11: FileCreate (Tạo Tập Tin Mới)¤

    • Ý nghĩa: Tập tin mới được tạo hoặc bị ghi đè lên đĩa cứng.
    • Trường dữ liệu cốt lõi: ProcessGuid, Image, TargetFilename, CreationUtcTime.
    • Dấu hiệu đáng ngờ:
    • Tập tin thực thi (.exe, .dll, .ps1, .bat, .vbs, .hta, .cpl) được sinh ra trong các thư mục ghi tự do của người dùng: C:\Users\*\AppData\Local\Temp, C:\ProgramData, C:\Users\Public, C:\Windows\Temp.
    • Tệp tin được sinh trực tiếp vào thư mục tự khởi động (Startup Folder).

    EventID 15: FileCreateStreamHash (Alternate Data Streams - ADS)¤

    • Ý nghĩa: Dữ liệu được ghi vào luồng dữ liệu thay thế NTFS (filename:streamname).
    • Trường dữ liệu cốt lõi: TargetFilename, Hashes, Contents.
    • Dấu hiệu đáng ngờ: Kẻ tấn công ẩn giấu mã độc hoặc script thực thi phía sau một tệp văn bản hợp lệ (report.txt:payload.exe), ngoài luồng định danh nguồn tải xuống hợp lệ Zone.Identifier.

    EventID 23 và 26: File Delete (Xóa Tập Tin)¤

    • EventID 23 (FileDeleteArchived): Sysmon ghi nhận sự kiện xóa tập tin và đồng thời lưu một bản sao an toàn vào thư mục lưu trữ C:\Sysmon phục vụ giải mã, trích xuất mã độc.
    • EventID 26 (FileDeleteDetected): Chỉ ghi nhận sự kiện xóa mà không lưu lại bản sao (giảm tải dung lượng đĩa).
    • Dấu hiệu đáng ngờ: Ransomware tiến hành xóa hàng loạt tệp tin dữ liệu gốc sau khi mã hóa, hoặc xóa bản sao lưu phục hồi hệ thống Shadow Copies (vssadmin delete shadows).

    EventID 27, 28 và 29: Kiểm Soát Tập Tin Thực Thi Nâng Cao¤

    • EventID 27 (FileBlockExecutable): Sysmon ngăn chặn không cho phép ghi tập tin thực thi theo chính sách cấu hình bảo vệ.
    • EventID 28 (FileBlockShredding): Sysmon phát hiện và ngăn chặn hành vi băm nát tệp tin (Anti-Forensics File Shredding) của mã độc phá hủy dữ liệu (Wiper).
    • EventID 29 (FileExecutableDetected): Phát hiện tệp tin cấu trúc thực thi PE được tạo mới ngay cả khi tệp tin bị đổi phần mở rộng sang .txt, .jpg, .pdf nhằm qua mặt bộ lọc.

    Phân Nhóm 5: Duy Trì Sự Hiện Diện Bằng Registry (Registry Persistence)¤

    EventID Tên Sự Kiện Ý Nghĩa Kỹ Thuật Điểm Nóng Cần Giám Sát
    Event 12 RegistryCreate / Delete Tạo hoặc xóa một Key/Value trong Registry. Xóa khóa cấu hình phòng thủ, xóa dịch vụ hệ thống.
    Event 13 RegistrySetValue Thiết lập giá trị dữ liệu cho một tham số Registry. Ghi đường dẫn mã độc vào Run, RunOnce, IFEO, Winlogon Shell.
    Event 14 RegistryRename Đổi tên Key/Value nhằm trốn tránh các luật giám sát theo chuỗi ký tự cứng. Đổi tên khóa Run sang tên ngẫu nhiên để che giấu.

    Các nhánh Registry nhạy cảm thường bị khai thác (Điểm nóng Event 13):¤

    • HKLM\Software\Microsoft\Windows\CurrentVersion\Run và RunOnce
    • HKCU\Software\Microsoft\Windows\CurrentVersion\Run và RunOnce
    • HKLM\Software\Microsoft\Windows NT\CurrentVersion\Image File Execution Options (IFEO - Debugger hijack)
    • HKLM\System\CurrentControlSet\Services\*\ImagePath (Cài đặt dịch vụ độc hại)
    • HKLM\Software\Microsoft\Windows NT\CurrentVersion\Winlogon\Userinit và Shell

    Phân Nhóm 6: Cơ Chế Duy Trì Bằng WMI (WMI Persistence)¤

    Kỹ thuật WMI Persistence (T1546.003) yêu cầu sự phối hợp chặt chẽ của bộ ba sự kiện:

    • EventID 19 (WmiEventFilter activity detected): Đăng ký điều kiện lọc WQL (Ví dụ: kích hoạt khi hệ thống khởi động hoặc người dùng đăng nhập).
    • EventID 20 (WmiEventConsumer activity detected): Đăng ký hành động thực thi (CommandLineEventConsumer gọi PowerShell hoặc Script).
    • EventID 21 (WmiEventConsumerToFilter activity detected): Gắn kết Filter với Consumer tạo thành cơ chế kích hoạt hoàn chỉnh.

    Khi xuất hiện đồng thời Event 19, 20 và 21 trong thời gian ngắn mà Consumer trỏ vào powershell.exe, cmd.exe hoặc script ẩn, đây là dấu hiệu mã độc APT duy trì hiện diện không dùng tệp (Fileless Persistence).

    Phân Nhóm 7: Đường Ống Giao Tiếp và Thao Tác Đĩa (Pipes và Raw Access)¤

    EventID 9: RawAccessRead (Đọc Trực Tiếp Thiết Bị Lưu Trữ)¤

    • Ý nghĩa: Tiến trình vượt qua tầng điều khiển hệ thống tập tin (File System API) để đọc trực tiếp bề mặt đĩa cứng (\\.\PhysicalDrive0 hoặc \\.\C:).
    • Dấu hiệu đáng ngờ: Ngoại trừ phần mềm sao lưu hoặc diệt virus, nếu tiến trình người dùng thực hiện đọc đĩa thô, mục đích thường là sao chép bảng MFT, đọc lậu tệp cơ sở dữ liệu xác thực NTDS.dit, SAM Registry hoặc mã độc Wiper chuẩn bị phá hủy cấu trúc bảng phân vùng.

    EventID 17 và 18: Named Pipe (Tạo và Kết Nối Đường Ống Giao Tiếp)¤

    • EventID 17 (PipeCreated): Tạo Named Pipe phục vụ giao tiếp nội bộ giữa các tiến trình.
    • EventID 18 (PipeConnected): Tiến trình kết nối vào Named Pipe đã tạo.
    • Dấu hiệu nhận diện công cụ tấn công:
    • PsExec: Khởi tạo named pipe dạng \PSEXESVC.
    • Cobalt Strike: Thường sử dụng mẫu pipe mặc định như \MSSE-*-server, \status_*, \msagent_*.
    • SMBExec: Đường ống ngẫu nhiên phục vụ điều khiển phiên lệnh qua cổng 445/SMB.

    Phân Nhóm 8: Cấu Hình và Nhật Ký Vận Hành (Configuration và Health)¤

    • EventID 4 (Sysmon service state changed): Trạng thái dịch vụ Sysmon thay đổi (Started hoặc Stopped). Sự kiện Stopped cần kích hoạt cảnh báo an ninh P1 ngay lập tức vì đây là dấu hiệu kẻ tấn công gỡ dịch vụ hoặc làm tê liệt hệ thống giám sát.
    • EventID 6 (Driver loaded): Trình điều khiển kernel (.sys) được nạp. Giám sát các driver không có chữ ký số hoặc driver bị khai thác lỗ hổng nhằm leo thang đặc quyền kernel (BYOVD - Bring Your Own Vulnerable Driver).
    • EventID 16 (Sysmon config state changed): Tệp tin cấu hình Sysmon bị thay đổi, hiển thị hàm băm cấu hình mới. Báo hiệu cấu hình bị quản trị viên cập nhật hoặc kẻ tấn công nới lỏng bộ lọc nhằm che giấu hành vi.
    • EventID 24 (ClipboardChange): Dữ liệu khay nhớ tạm hệ thống bị thay đổi. Hữu ích trong truy vết mã độc đánh cắp mật khẩu (Stealer) hoặc mã độc thay đổi địa chỉ ví tiền điện tử (Clipper).
    • EventID 255 (Error): Lỗi vận hành nội bộ của Sysmon (hết bộ nhớ đệm, lỗi phân tích cú pháp cấu hình, lỗi giao tiếp kernel minifilter).

    Cẩm Nang Cú Pháp và Cách Dùng SPL Thực Chiến Cho SOC¤

    Ngôn ngữ truy vấn dữ liệu Splunk Search Processing Language (SPL) là công cụ tác chiến hàng ngày của chuyên viên SOC. Toàn bộ câu lệnh trong SPL hoạt động theo cơ chế đường ống dẫn (Unix Pipeline |), trong đó dữ liệu đầu ra của câu lệnh phía trước trở thành dữ liệu đầu vào của câu lệnh phía sau.

    Quy tắc vàng về hiệu năng trong SOC: Lọc dữ liệu càng sớm càng tốt ở đầu đường ống (Search Early, Filter Early). Không bao giờ dùng lệnh tìm kiếm chung chung như * hoặc để search ở cuối đường ống sau khi đã kéo hàng triệu sự kiện thô về Search Head.

    1. Bản Đồ 15 Lệnh SPL Cốt Lõi Trong SOC¤

    flowchart LR
    A["1. Thu Thập & Lọc<br/>search, fields, where"] --> B["2. Chuẩn Hóa & Bóc Tách<br/>eval, rex, rename, lookup"]
    B --> C["3. Thống Kê & Phân Tích<br/>stats, dedup, sort, timechart"]
    C --> D["4. Nâng Cao & Tăng Tốc<br/>streamstats, eventstats, tstats"]
    Hold "Alt" / "Option" to enable pan & zoom

    2. Thẻ Tra Cứu Chi Tiết 15 Lệnh SPL¤

    Lệnh 1: search (Lọc và Tìm Kiếm Dữ Liệu Ban Đầu)¤

    • Chức năng: Tìm kiếm các sự kiện khớp với từ khóa, trường dữ liệu và điều kiện logic boolean.
    • Cú pháp chuẩn: search index=<tên_index> sourcetype=<tên_sourcetype> [điều kiện]
    • Lưu ý thực chiến:
    • Các toán tử boolean AND, OR, NOT bắt buộc phải viết hoa.
    • Hạn chế tối đa dùng ký tự đại diện * ở đầu chuỗi (ví dụ: *password sẽ bắt Splunk quét toàn bộ từ điển chỉ mục, gây chậm gấp hàng chục lần so với password*).
    • Ví dụ mẫu SOC:
      Bash
      index=windows sourcetype="XmlWinEventLog:Security" EventCode=4625 (TargetUserName="admin*" OR TargetUserName="root")

    Lệnh 2: table (Trích Xuất Bảng Dữ Liệu Hiển Thị)¤

    • Chức năng: Chỉ giữ lại các trường được chỉ định và hiển thị dưới dạng bảng theo đúng thứ tự khai báo.
    • Cú pháp: table <field1> <field2> ... <fieldN>
    • Ví dụ mẫu SOC:
      Bash
      index=windows sourcetype="XmlWinEventLog:Security" EventCode=4624
| table _time host TargetUserName LogonType IpAddress

    Lệnh 3: fields (Tối Ưu Hóa Bộ Nhớ Và Băng Thông)¤

    • Chức năng: Giữ lại (fields +) hoặc loại bỏ (fields -) các trường dữ liệu khỏi bộ nhớ trung gian của đường ống dẫn mà không làm thay đổi định dạng sự kiện gốc.
    • Lưu ý thực chiến: Khác với table (lệnh biến đổi định dạng), fields + giúp Search Head yêu cầu Indexer chỉ nạp đúng các trường cần thiết, tiết kiệm tới 70% bộ nhớ RAM khi xử lý tập dữ liệu lớn.
    • Ví dụ mẫu SOC:
      Bash
      index=firewall sourcetype="pan:traffic"
| fields + _time src_ip dest_ip dest_port action

    Lệnh 4: rename (Đổi Tên Trường Trực Quan)¤

    • Chức năng: Đổi tên một hoặc nhiều trường dữ liệu để phục vụ báo cáo hoặc ánh xạ tạm thời theo chuẩn Common Information Model (CIM).
    • Cú pháp: rename <old_field> AS <new_field>
    • Ví dụ mẫu SOC:
      Bash
      index=windows EventCode=4624
| rename TargetUserName AS user, IpAddress AS src_ip, host AS dest_host
| table _time user src_ip dest_host

    Lệnh 5: dedup (Loại Bỏ Bản Ghi Trùng Lặp)¤

    • Chức năng: Giữ lại bản ghi đầu tiên và loại bỏ các bản ghi trùng lặp tiếp theo dựa trên tổ hợp trường được chọn.
    • Cú pháp: dedup <field1> [field2] ...
    • Ví dụ mẫu SOC: Tìm danh sách các địa chỉ IP bên ngoài từng quét cổng hệ thống trong ngày mà không cần xem hàng nghìn bản ghi trùng:
      Bash
      index=firewall action=blocked
| dedup src_ip
| table src_ip dest_port

    Lệnh 6: sort (Sắp Xếp Bản Ghi)¤

    • Chức năng: Sắp xếp kết quả tăng dần (+ hoặc mặc định) hoặc giảm dần (-), có thể giới hạn số lượng bản ghi hiển thị.
    • Cú pháp: sort [-/+]<field> [limit=<N>]
    • Ví dụ mẫu SOC: Top 10 tài khoản bị đăng nhập sai nhiều nhất:
      Bash
      index=windows EventCode=4625
| stats count by TargetUserName
| sort - count
| head 10

    Lệnh 7: stats (Tập Hợp Thống Kê Dữ Liệu)¤

    • Chức năng: Thực hiện các phép toán tổng hợp số học và thống kê trên các trường dữ liệu.
    • Các hàm thống kê trọng yếu:
    • count: Đếm tổng số bản ghi.
    • distinct_count(X) hoặc dc(X): Đếm số lượng giá trị duy nhất (không trùng lặp).
    • values(X): Liệt kê danh sách các giá trị duy nhất của trường X (đã lọc trùng).
    • list(X): Liệt kê toàn bộ các giá trị theo thứ tự xuất hiện (giữ nguyên bản ghi trùng).
    • earliest(_time), latest(_time): Mốc thời gian đầu tiên và cuối cùng xuất hiện sự kiện.
    • avg(X), sum(X), min(X), max(X): Tính trung bình, tổng, giá trị nhỏ nhất/lớn nhất.
    • Ví dụ mẫu SOC:
      Bash
      index=windows EventCode=4625
| stats count as failed_attempts, dc(TargetUserName) as targeted_users, values(TargetUserName) as user_list by IpAddress
| where failed_attempts > 10

    Lệnh 8: eval (Tính Toán Logic Và Xử Lý Biểu Thức)¤

    • Chức năng: Tạo trường mới hoặc ghi đè giá trị trường dựa trên phép tính số học, logic điều kiện hoặc hàm chuỗi.
    • Các hàm thường dùng trong SOC:
    • case(đk1, giá_trị_1, đk2, giá_trị_2, 1=1, mặc_định): Điều kiện rẽ nhánh nhiều trường hợp.
    • if(điều_kiện, đúng, sai): Điều kiện rẽ nhánh đơn.
    • len(chuỗi): Đo độ dài chuỗi ký tự (hữu ích săn DNS Tunneling).
    • lower(chuỗi), upper(chuỗi): Chuyển đổi định dạng chữ thường/chữ hoa.
    • strftime(thời_gian, "%Y-%m-%d %H:%M:%S"): Định dạng thời gian hiển thị.
    • strptime(chuỗi_thời_gian, "%Y-%m-%d"): Chuyển chuỗi sang Unix Epoch Timestamp.
    • Ví dụ mẫu SOC:
      Bash
      index=web_logs
| eval response_category=case(
    status>=200 AND status<300, "Success_2xx",
    status>=400 AND status<500, "Client_Error_4xx",
    status>=500, "Server_Error_5xx",
    1=1, "Other"
  )
| stats count by response_category

    Lệnh 9: where (Bộ Lọc Điều Kiện Logic Sau Thống Kê)¤

    • Chức năng: Lọc dữ liệu bằng biểu thức tính toán số học, so sánh giá trị giữa hai trường dữ liệu với nhau.
    • Phân biệt với lệnh search:
    • search chỉ kiểm tra trường với một giá trị cố định (search port=80).
    • where có thể so sánh hai trường trực tiếp với nhau (where src_ip == dest_ip hoặc where duration > threshold).
    • Ví dụ mẫu SOC:
      Bash
      index=network sourcetype="zeek:conn"
| stats sum(orig_bytes) as sent_bytes, sum(resp_bytes) as received_bytes by id.orig_h
| where sent_bytes > received_bytes * 10

    Lệnh 10: rex (Trích Xuất Trường Bằng Biểu Thức Chính Quy Regex)¤

    • Chức năng: Trích xuất thông tin chưa được Splunk tự động nhận diện từ bản ghi thô _raw bằng cú pháp Named Capture Group (?<tên_trường>mẫu_regex).
    • Cú pháp: rex field=<tên_trường> "(?<tên_trường_mới>biểu_thức_regex)"
    • Ví dụ mẫu SOC: Bóc tách tên tiến trình và tham số dòng lệnh từ bản ghi thô:
      Bash
      index=linux sourcetype="linux_audit" "type=EXECVE"
| rex field=_raw "a0=\"(?<executed_binary>[^\"]+)\""
| rex field=_raw "a1=\"(?<first_argument>[^\"]+)\""
| table _time host executed_binary first_argument

    Lệnh 11: lookup (Tra Cứu Danh Mục Bổ Trợ)¤

    • Chức năng: Ghép nối dữ liệu sự kiện với bảng tra cứu ngoài (CSV hoặc KV Store) để bổ sung bối cảnh danh sách tài sản, danh tính nhân sự hoặc đối soát Threat Intel.
    • Cú pháp: lookup <tên_file_lookup> <khóa_khớp> OUTPUT <trường_cần_lấy>
    • Ví dụ mẫu SOC:
      Bash
      index=firewall action=allowed
| lookup threat_intel_ip.csv ip AS dest_ip OUTPUT threat_category, confidence_score
| where isnotnull(threat_category)
| table _time src_ip dest_ip threat_category confidence_score

    Lệnh 12: timechart (Trực Quan Hóa Chuỗi Thời Gian)¤

    • Chức năng: Thống kê dữ liệu tổng hợp theo từng khoảng thời gian (Bucket) để vẽ biểu đồ đường, biểu đồ cột hoặc phát hiện bất thường theo dòng thời gian.
    • Tham số quan trọng: span=10m (khoảng 10 phút), span=1h (khoảng 1 giờ), span=1d (khoảng 1 ngày).
    • Ví dụ mẫu SOC:
      Bash
      index=windows EventCode=4625
| timechart span=15m count by TargetUserName

    Lệnh 13: bin / bucket (Phân Khoảng Dữ Liệu)¤

    • Chức năng: Gom nhóm các giá trị số hoặc thời gian thành từng khoảng cố định.
    • Cú pháp: bin _time span=1h hoặc bin bytes span=100000
    • Ví dụ mẫu SOC:
      Bash
      index=proxy
| bin bytes span=1000000 as byte_range
| stats count by byte_range

    Lệnh 14: streamstats và eventstats (Tính Toán Thống Kê Theo Luồng)¤

    • eventstats: Tính toán giá trị thống kê trên toàn bộ tập kết quả hiện thời và gán ngược giá trị đó vào từng bản ghi mà không làm mất đi chi tiết sự kiện ban đầu. Cực kỳ mạnh mẽ để tính độ lệch chuẩn (Z-Score) và so sánh từng bản ghi với mức trung bình của toàn mạng.
    • streamstats: Tính toán tích lũy theo luồng sự kiện trôi qua (Running/Cumulative calculation). Dùng để tính khoảng thời gian giữa 2 sự kiện liên tiếp của cùng 1 IP (phát hiện C2 Beaconing).
    • Ví dụ mẫu SOC (Tính khoảng thời gian delta giữa 2 kết nối):
      Bash
      index=network sourcetype="zeek:conn" id.resp_p=443
| sort 0 id.orig_h _time
| streamstats current=true window=2 range(_time) as time_diff by id.orig_h
| where time_diff > 0
| stats count avg(time_diff) as mean_interval stdev(time_diff) as jitter by id.orig_h id.resp_h

    Lệnh 15: tstats (Tối Ưu Tăng Tốc Tìm Kiếm Trên Data Model)¤

    • Chức năng: Truy vấn trực tiếp trên các tệp chỉ mục tóm tắt tăng tốc .tsidx của Data Model đã được Accelerated. Bỏ qua hoàn toàn việc đọc tệp _raw trên đĩa cứng, giúp tốc độ tìm kiếm nhanh hơn từ 10 đến 100 lần.
    • Cú pháp: | tstats count from datamodel=<Tên_DataModel> where [điều_kiện] by [trường]
    • Ví dụ mẫu SOC:
      Bash
      | tstats summariesonly=t count from datamodel=Authentication.Authentication
  where Authentication.action="failure"
  by Authentication.src Authentication.user
| rename Authentication.* as *
| where count > 20

    3. Top 5 Kịch Bản Săn Lùng Mối Đe Dọa (Threat Hunting Templates)¤

    Kịch Bản 1: Săn Lùng Tấn Công Password Spraying¤

    • Ý tưởng săn lùng: Kẻ tấn công thử một vài mật khẩu phổ biến (Spring2026!, Welcome123) trên hàng loạt tài khoản người dùng khác nhau từ cùng một địa chỉ IP nhằm tránh bị khóa tài khoản đơn lẻ.
      Bash
      index=windows sourcetype="XmlWinEventLog:Security" EventCode=4625
| stats count as failed_attempts, dc(TargetUserName) as unique_users, values(TargetUserName) as targeted_users by IpAddress
| where unique_users >= 5 AND failed_attempts >= 10
| eval ratio = round(failed_attempts / unique_users, 2)
| table IpAddress unique_users failed_attempts ratio targeted_users
| sort - unique_users

    Kịch Bản 2: Săn Lùng Kết Nối Máy Chủ Điều Khiển C2 (Beaconing Jitter)¤

    • Ý tưởng săn lùng: Mã độc gửi tín hiệu Heartbeat theo chu kỳ thời gian cố định. Tỷ số biến thiên (Jitter Ratio = Độ lệch chuẩn / Thời gian trung bình) của mã độc thường dưới 20% (0.2).
      Bash
      index=network sourcetype="zeek:conn"
| sort 0 id.orig_h id.resp_h _time
| streamstats window=2 current=true range(_time) as delta_time by id.orig_h id.resp_h
| where delta_time > 0
| stats count, avg(delta_time) as avg_interval, stdev(delta_time) as jitter by id.orig_h id.resp_h id.resp_p
| where count >= 30 AND isnotnull(jitter) AND avg_interval >= 5
| eval jitter_ratio = round(jitter / avg_interval, 3)
| where jitter_ratio <= 0.20
| table id.orig_h id.resp_h id.resp_p count avg_interval jitter jitter_ratio
| sort jitter_ratio

    Kịch Bản 3: Săn Lùng Web Shell Qua Bất Thường Tỷ Lệ HTTP 200/404¤

    • Ý tưởng săn lùng: Web shell nhận các truy vấn POST trực tiếp và hầu hết đều trả về mã 200 OK mà không bao giờ gặp lỗi 404 hay chuyển hướng 302.
      Bash
      index=web_proxy sourcetype="ms:iis:auto"
| search cs_method=POST cs_uri_stem IN ("*.aspx", "*.php", "*.jsp")
| stats count as total_post,
        count(eval(sc_status==200)) as success_count,
        count(eval(sc_status==404)) as not_found_count,
        values(cs_uri_stem) as target_files,
        avg(sc_bytes) as avg_response_size by c_ip cs_uri_stem
| eval success_ratio = round((success_count / total_post) * 100, 2)
| where total_post >= 10 AND success_ratio >= 90 AND not_found_count == 0
| table c_ip cs_uri_stem total_post success_ratio avg_response_size
| sort - total_post

    Kịch Bản 4: Săn Lùng Công Cụ Nội Tại (LOLBins) Chạy Từ Đường Dẫn Bất Thường¤

    • Ý tưởng săn lùng: Kẻ tấn công sao chép các công cụ hệ thống hợp lệ (cmd.exe, powershell.exe, certutil.exe) vào thư mục ghi tự do của người dùng để trốn tránh bộ lọc.
      Bash
      index=windows sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
| eval binary_name = lower(mvindex(split(Image, "\\"), -1))
| search binary_name IN ("cmd.exe", "powershell.exe", "certutil.exe", "bitsadmin.exe", "mshta.exe", "rundll32.exe", "cscript.exe")
| search Image IN ("*\\Users\\*", "*\\AppData\\*", "*\\Temp\\*", "*\\ProgramData\\*", "*\\Public\\*")
| table _time host User ParentImage Image CommandLine CurrentDirectory
| sort - _time

    Kịch Bản 5: Săn Lùng Rò Rỉ Dữ Liệu Ngoại Biên (Outbound Data Exfiltration)¤

    • Ý nghĩa: Sử dụng eventstats để tính toán lượng byte truyền tải trung bình và độ lệch chuẩn của toàn mạng, từ đó tìm kiếm các máy trạm truyền lượng dữ liệu đột biến (Z-Score > 3).
      Bash
      index=network sourcetype="zeek:conn"
| where NOT cidrmatch("10.0.0.0/8", id.resp_h) AND NOT cidrmatch("192.168.0.0/16", id.resp_h) AND NOT cidrmatch("172.16.0.0/12", id.resp_h)
| stats sum(orig_bytes) as total_bytes_sent by id.orig_h
| eventstats avg(total_bytes_sent) as global_avg, stdev(total_bytes_sent) as global_std
| eval z_score = round((total_bytes_sent - global_avg) / global_std, 2)
| where z_score >= 3.0
| eval megabytes_sent = round(total_bytes_sent / 1024 / 1024, 2)
| table id.orig_h megabytes_sent z_score
| sort - megabytes_sent

    1. Dấu Vết Thực Thi Lệnh Trên Windows (Evidence of Execution)¤

    Khi kẻ tấn công chạy một phần mềm độc hại hoặc một công cụ dòng lệnh, hệ điều hành Windows luôn để lại các dấu vết thực thi bất biến dù tệp tin gốc có bị xóa khỏi đĩa.

    1.1. Windows Prefetch (C:\Windows\Prefetch\*.pf)¤

    • Bản chất cơ chế: Tính năng quản lý bộ nhớ của Windows nạp trước dữ liệu vào RAM để tăng tốc khởi động ứng dụng.
    • Quy tắc đặt tên: <TÊN_TIẾN_TRÌNH>-<HASH_ĐƯỜNG_DẪN>.pf (Ví dụ: CMD.EXE-A1B2C3D4.pf).
    • Thông tin trích xuất:
    • Thời điểm thực thi gần nhất (Last Run Time) và tối đa 8 mốc thời gian thực thi trước đó.
    • Tổng số lần khởi chạy (Run Count).
    • Danh sách toàn bộ các tệp tin, thư mục và DLL mà tiến trình này đã nạp vào bộ nhớ trong 10 giây đầu tiên hoạt động (giúp tìm ra tệp mã độc được gọi ngầm).
    • Công cụ phân tích: PECmd.exe (Eric Zimmerman).
      Text Only
      PECmd.exe -f "C:\Windows\Prefetch\POWERSHELL.EXE-B00B1234.pf" --csv C:\temp\output

    1.2. Shimcache (Application Compatibility Cache)¤

    • Vị trí lưu trữ: SYSTEM\CurrentControlSet\Control\Session Manager\AppCompatCache.
    • Đặc tính: Được lưu trong bộ nhớ kernel và chỉ ghi xuống Registry khi hệ thống tắt máy (Shutdown) hoặc khởi động lại.
    • Thông tin trích xuất:
    • Đường dẫn đầy đủ của tệp tin thực thi (kể cả tệp chạy từ ổ đĩa USB cắm ngoài).
    • Kích thước tệp tin (File Size).
    • Thời điểm chỉnh sửa gần nhất của tệp ($STANDARD_INFORMATION Last Modified Time).
    • Cờ thực thi (Executed Flag: True hoặc False).
    • Công cụ phân tích: AppCompatCacheParser.exe.
      Text Only
      AppCompatCacheParser.exe -f "C:\Windows\System32\config\SYSTEM" --csv C:\temp\output

    1.3. Amcache (C:\Windows\appcompat\Programs\Amcache.hve)¤

    • Đặc tính vượt trội: Là mỏ vàng pháp y số ghi lại chi tiết mọi chương trình thực thi, trình điều khiển (Driver) và tệp tin cài đặt.
    • Thông tin trích xuất:
    • Mã băm SHA-1 của tệp tin thực thi (giúp tra cứu ngay trên VirusTotal mà không cần tìm lại file gốc).
    • Đường dẫn tệp, thời điểm biên dịch (Compilation Timestamp).
    • Khóa cài đặt phần mềm và các DLL liên kết.
    • Công cụ phân tích: AmcacheParser.exe.
      Text Only
      AmcacheParser.exe -f "C:\Windows\appcompat\Programs\Amcache.hve" --csv C:\temp\output

    1.4. Background Activity Moderator (BAM / DAM)¤

    • Vị trí Registry: SYSTEM\CurrentControlSet\Services\bam\UserSettings\<UserSID>.
    • Đặc tính: Tính năng tiết kiệm pin quản lý ứng dụng chạy nền của Windows.
    • Thông tin trích xuất: Lưu chính xác đường dẫn thực thi kèm mốc thời gian thực tế chính xác tới từng giây mà người dùng đó đã kích hoạt ứng dụng.

    2. Dấu Vết Tương Tác Tệp Tin và Thư Mục (File Knowledge & Access)¤

    Dùng để chứng minh kẻ tấn công hoặc nội gián đã mở thư mục nào, duyệt tệp tin nào và đánh cắp dữ liệu gì:

    • Shellbags (UsrClass.dat): Lưu trữ tùy chọn hiển thị thư mục của người dùng trong Windows Explorer. Chứng minh người dùng hoặc kẻ tấn công đã từng duyệt vào một thư mục cụ thể, ngay cả khi thư mục đó nằm trên USB đã rút ra hoặc thư mục mạng đã ngắt kết nối.
    • LNK Shortcut Files (%APPDATA%\Microsoft\Windows\Recent\): Tự động sinh ra khi người dùng mở tệp. Chứa thông tin về đường dẫn tệp gốc, kích thước tệp, loại ổ đĩa, địa chỉ MAC của card mạng máy tính và thời điểm mở tệp.
    • Jumplists (%APPDATA%\Microsoft\Windows\Recent\AutomaticDestinations\): Danh sách các tệp tin thường dùng gắn với thanh Taskbar của từng ứng dụng (chứng minh tệp tài liệu nào được mở bằng Word/Excel).
    • Recycle Bin Forensics (C:\$Recycle.Bin\<UserSID>\):
    • Tệp $I<random>: Chứa siêu dữ liệu (Metadata) gồm đường dẫn tệp gốc, kích thước và mốc thời gian xóa.
    • Tệp $R<random>: Chứa nội dung dữ liệu thực tế của tệp tin bị xóa.

    3. Hệ Thống Tập Tin NTFS và Kỹ Thuật Phát Hiện Timestomping¤

    Mọi tệp tin trên hệ thống tập tin NTFS đều có 2 thuộc tính thời gian nằm trong bảng Master File Table ($MFT):

    1. $STANDARD_INFORMATION ($SI): Hiển thị trực tiếp trên giao diện Windows Explorer (Kẻ tấn công có thể dễ dàng sửa đổi mốc thời gian này bằng công cụ Timestomping như timestomp.exe hoặc PowerShell).
    2. $FILE_NAME ($FN): Chỉ được nhân hệ điều hành (Kernel) cập nhật khi đổi tên hoặc di chuyển tệp. Các công cụ thông thường không thể chỉnh sửa được $FN.

    Quy tắc vàng phát hiện Timestomping: Nếu mốc thời gian khởi tạo của $STANDARD_INFORMATION nhỏ hơn mốc thời gian của $FILE_NAME (tức là ngày tạo hiển thị trên Explorer cổ hơn cả ngày hệ điều hành ghi nhận trong $FN), tệp tin đó 100% đã bị can thiệp làm sai lệch thời gian (Timestomped T1070.006).

    • Công cụ phân tích $MFT: MFTECmd.exe.
      Text Only
      MFTECmd.exe -f "C:\$MFT" --csv C:\temp\output --csvf mft_analysis.csv

    1. Phân Tích Nhật Ký Tường Lửa Thế Hệ Mới (Palo Alto và Fortinet)¤

    1.1. Chiến Lược Phân Tích Quyết Định Xử Lý (Action Triage)¤

    Chuyên viên SOC cần phân biệt rõ bản chất của hai trạng thái xử lý trên Firewall: * action=drop / action=deny (Bị chặn): Đòn tấn công thăm dò từ bên ngoài Internet đã bị bộ lọc tường lửa chặn đứng ở cửa ngõ. Đây là hiện tượng bình thường (Background Internet Noise). Chỉ nâng mức ưu tiên nếu xuất phát từ IP chuyên dụng nội bộ hoặc tấn công liên tục vào dịch vụ trọng yếu. * action=allow / action=accept (Cho phép đi qua): Nếu xuất hiện cảnh báo mã độc (Threat Log) hoặc lưu lượng truy cập IP độc hại mà trạng thái là allow, đây là sự cố mức cao (P1/P2). Kẻ tấn công đã vượt qua tường lửa và tiếp cận thành công máy chủ nội bộ.

    1.2. Săn Lùng Rò Rỉ Dữ Liệu Qua Dung Lượng Outbound (Data Exfiltration)¤

    Bash
    # Truy vấn các phiên kết nối gửi lượng dữ liệu đột biến ra ngoài Internet:
index=firewall sourcetype="pan:traffic" action=allow
| where NOT cidrmatch("10.0.0.0/8", dest_ip) AND NOT cidrmatch("192.168.0.0/16", dest_ip) AND NOT cidrmatch("172.16.0.0/12", dest_ip)
| stats sum(bytes_sent) as total_bytes_sent, sum(bytes_received) as total_bytes_rcvd by src_ip dest_ip dest_port app
| eval mb_sent = round(total_bytes_sent / 1024 / 1024, 2)
| where mb_sent > 50 AND total_bytes_sent > total_bytes_rcvd * 5
| sort - mb_sent

    2. Cẩm Nang Bóc Tách Nhật Ký Cảm Biến Mạng Zeek NSM¤

    Zeek (trước đây là Bro) không phát cảnh báo theo chữ ký thô sơ, mà chuyển đổi toàn bộ lưu lượng mạng thành các tệp nhật ký có cấu trúc phân tầng theo từng giao thức:

    2.1. Phân Tích Nhật Ký Kết Nối (conn.log)¤

    Tệp conn.log ghi lại tóm tắt của mọi phiên giao tiếp TCP/UDP/ICMP diễn ra trên mạng:

    Trường Dữ Liệu Kiểu Dữ Liệu Ý Nghĩa Kỹ Thuật Trong Phân Tích SOC
    id.orig_h / id.orig_p IP / Port Địa chỉ IP và cổng của bên phát sinh kết nối ban đầu (Originator).
    id.resp_h / id.resp_p IP / Port Địa chỉ IP và cổng của bên nhận và phản hồi kết nối (Responder).
    proto String Giao thức truyền vận (tcp, udp, icmp).
    duration Float Thời gian tồn tại của phiên tính theo giây.
    orig_bytes / resp_bytes Integer Số lượng byte dữ liệu tầng ứng dụng (payload) thực tế được trao đổi.
    conn_state String Trạng thái kết thúc của phiên kết nối (Trọng tâm phân tích SOC).
    • Giải mã các cờ trạng thái conn_state trọng yếu:
    • S0 (Connection attempt seen, no reply): Máy nguồn gửi gói tin SYN nhưng không nhận được phản hồi SYN-ACK. Xuất hiện hàng loạt địa chỉ đích khác nhau với cờ S0 là dấu hiệu rõ ràng của hành vi quét cổng mạng (TCP SYN Port Scan).
    • SF (Normal establishment and termination): Phiên kết nối bắt tay 3 bước thành công và ngắt kết nối đúng chuẩn (gửi FIN).
    • REJ (Connection attempt rejected): Máy đích chủ động từ chối kết nối bằng cách gửi cờ RST (cổng đích đang đóng hoặc bị firewall cục bộ chặn).
    • RSTO / RSTR: Kết nối bị đặt lại (Reset) bởi máy nguồn (RSTO) hoặc máy đích (RSTR).

    2.2. Phân Tích Nhật Ký Truy Vấn Tên Miền (dns.log)¤

    • query: Tên miền được yêu cầu phân giải.
    • qtype_name: Loại bản ghi DNS (A, AAAA, TXT, CNAME, PTR, MX).
    • rcode_name: Mã kết quả trả về (NOERROR - thành công, NXDOMAIN - tên miền không tồn tại).
    • Dấu hiệu chỉ điểm tấn công:
    • Thuật toán sinh tên miền tự động (DGA): Tỷ lệ các truy vấn trả về mã lỗi NXDOMAIN tăng đột biến (mã độc thử hàng trăm tên miền ngẫu nhiên để tìm máy chủ C2 đang hoạt động).
    • Đường hầm truyền dữ liệu qua DNS (DNS Tunneling): Tần suất yêu cầu bản ghi TXT cao bất thường; các subdomain có độ dài vượt quá 50 ký tự và chuỗi ký tự có độ phức tạp ngẫu nhiên cao.

    2.3. Phân Tích Nhật Ký Mã Hóa và Nhận Dạng TLS (ssl.log)¤

    • server_name (SNI - Server Name Indication): Tên miền máy chủ trong gói tin Client Hello (chưa mã hóa).

    4. Công Thức Toán Học Săn Lùng Mối Đe Dọa Mạng Nâng Cao¤

    4.1. Thuật Toán Jitter Ratio: Phát Hiện Kết Nối Máy Chủ Điều Khiển C2 (Beaconing)¤

    Phần lớn mã độc hiện đại đều sử dụng cơ chế liên lạc định kỳ (Beaconing) kèm theo một tỷ lệ biến thiên thời gian ngẫu nhiên (Jitter) nhằm tránh các bộ lọc thời gian cố định đơn giản:

    Giả sử trong khoảng thời gian quan sát, có \(N\) kết nối liên tiếp giữa máy trạm \(A\) và máy chủ \(B\). Khoảng thời gian giữa 2 kết nối liên tiếp là \(\Delta t_i = t_{i} - t_{i-1}\).

    • Thời gian trễ trung bình (Mean Interval): $\(\mu = \frac{1}{N-1} \sum_{i=2}^{N} \Delta t_i\)$

    • Độ lệch chuẩn thời gian (Standard Deviation): $\(\sigma = \sqrt{\frac{1}{N-1} \sum_{i=2}^{N} (\Delta t_i - \mu)^2}\)$

    • Tỷ số biến thiên thời gian (Jitter Ratio): $\(\text{Jitter Ratio} = \frac{\sigma}{\mu}\)$

    Tiêu chuẩn phân loại thực tế: * Các kết nối người dùng duyệt web thông thường có tính ngẫu nhiên rất cao: \(\text{Jitter Ratio} \ge 0.60\). * Các tác nhân mã độc (Cobalt Strike, Havoc, Sliver, Brute Ratel) dù có bật tính năng Sleep Jitter 20% thì cấu trúc toán học vẫn duy trì: \(\mathbf{\text{Jitter Ratio} \le 0.20}\).

    4.2. Thuật Toán Shannon Entropy: Phát Hiện Kênh Ngầm DNS Tunneling và Tên Miền DGA¤

    Độ hỗn loạn thông tin (Shannon Entropy) đo lường mức độ ngẫu nhiên của các ký tự xuất hiện trong một chuỗi tên miền \(S\) có độ dài \(n\):

    \[H(S) = - \sum_{i=1}^{k} P(c_i) \log_2 P(c_i)\]

    Trong đó: * \(k\) là số lượng ký tự phân biệt trong chuỗi. * \(P(c_i)\) là tần suất xuất hiện của ký tự \(c_i\) trong chuỗi.

    Tiêu chuẩn phân loại tên miền: * Tên miền từ vựng tiếng Anh / tiếng Việt chuẩn (google.com, vnexpress.net, microsoft.com): \(H(S) \le 2.8\). * Tên miền thuật toán DGA hoặc đường hầm nạp dữ liệu Hex/Base64 (v4x7a9q2k8m1z0.corp-tunnel.xyz): \(\mathbf{H(S) \ge 3.8}\). Khi \(H(S) \ge 3.8\) kết hợp độ dài tên miền \(> 40\) ký tự, tỷ lệ phát hiện True Positive lên tới trên 95%.
